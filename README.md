# シフト管理（申請者ページ／管理者ページ）

店舗のシフトを、スタッフからの希望集めから月のシフト作成まで通してやるための2画面。

- **申請者ページ**（スタッフ用・スマホ）… `index.html`
  カレンダーを塗るだけで希望を入力し、LINEに貼れる文章を作って送る。
- **管理者ページ**（店長用）… **このリポジトリから出て行った。**
  店舗管理アプリ（github.com/keiki-takemoto/store）の `shift/` に引っ越し。
  ここの `admin/` は新しい場所へ転送するだけのページ。
  共有している `shared/` の3ファイルは、あちらにも同じものを置いてある。
  **書式や通信を直すときは両方直すこと。**

## 2つをつなぐもの

`shared/shift-format.js` が希望シフトの書式そのもの。申請者ページが書き、
管理者ページが読む。**ここを直すときは必ず両方の画面で確かめること。**
古い「シフト作るくん」の `am / pm / off / 13.5〜` 形式も読める。

送られる文章の形：

```
【シフト希望】2026年10月
名前：田中

× 3, 7
午前のみ 5
時間 9日 13:00-17:00
ほかの日は終日OK

メモ：20日以降は少なめで
```

## 2つの使い方

**そのまま（置き場所なし）** … 希望はLINEで送ってもらい、管理者ページに貼り付ける。
データは各端末のブラウザ内のみ。設定も何も要らない。

**つないだ状態（おすすめ）** … Supabase を置き場所にすると、
スタッフが送った希望が店長の画面に1分以内に自動で出る。確定シフトをスタッフに公開もできる。
手順ページとSQLは、店舗管理アプリ側（`shift/setup.html`、`server/supabase.sql`）にある。

- 通信部分は `shared/sync.js` に集約。置き場所をSupabaseなどに替えるときはここだけ差し替える。
- 合言葉は2つ。スタッフ用（配るURLに入る）と管理用キー（店長の端末だけ）。
  **売上など、スタッフに見せないデータを足すときは、必ず管理用キー側だけで読み書きすること。**
- 届いた希望はスプレッドシートの「希望」タブにも溜まるので、そのままバックアップになる。

管理者ページの⚙設定から、ときどきJSONのバックアップも取ること。

## 直すとき

- 直したら `sw.js` の `CACHE = "shift-v1"` の番号を1つ上げる。上げないと古い画面が端末に残る。
- アイコンは `python3 make_icons.py`。
- mainに push すると GitHub Pages に反映される（1分ほど）。
